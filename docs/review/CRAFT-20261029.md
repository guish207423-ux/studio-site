## Critical

### C1 · 移动端标题层级倒置：区块标题比首页大标题还大
- **现象**：390 档实测英雄标题 `#top h1` = **39px / 900 / lh 40.95**；区块标题 `.section-head h2` = **40px / 900**。也就是说手机上一进页面，往下滚 1.2 屏出现的「服务范围」四个字比「我们把设计变成能运行的产品」更大。1440 档同样接近：h1 96px vs h2 76px，**比值 1.26**，字重完全相同（900 vs 900）。
- **位置**：`src/styles/globals.css:540` —— `.section-head__title { font-size: var(--fs-h1) }`。根源是**令牌用错**：区块标题取了 H1 的令牌（`--fs-h1: clamp(40px, 5.6vw, 76px)`），而现成的 `--fs-h2: clamp(24px, 3.2vw, 36px)` 在全站 7 个 `.section-head` 里一次都没被用上。
- **判据**：Apple HIG《Typography》要求标题层级靠字号建立、且「页面主标题是该页最大的文字」；常用的相邻层级音阶下限是 1.25（Bringhurst 的音阶在多级层级里取 ≥1.4）。实测 39/40 = **0.98**，方向是反的；1440 档 1.26 也只是刚过最小值，加上同字重 900，层级差只靠 20px 撑，读完没有任何「这是新章节」的感觉。
- **建议（CSS 级）**：
  ```css
  .section-head__title { font-size: var(--fs-h2); }   /* 36px @1440 / 24px @390 */
  /* 若嫌 36px 太弱，另建一级，不要复用 h1 令牌 */
  :root { --fs-h2-display: clamp(28px, 3.6vw, 44px); }
  @media (max-width: 767px) { .hero-title { font-size: clamp(32px, 9vw, 44px); } }
  ```
  验收线：`h1.fontSize >= 1.4 * h2.fontSize`，两档都要成立。

### C2 · 首屏第三行只有一个词「产品」，占行长 33%（390 档 21%），且是全站唯一 accent 大字
- **现象**：`#top h1` 断成三行，实测行盒宽度 **466 / 559 / 186**；第三行「产品」两个字独占一行，宽 186px = 最长行的 **33%**。390 档：**189 / 227 / 76**，末行 76px = **21%**。这行是 accent 绿 `rgb(168,217,58)`（`.hero-title-accent`，对比度 11.93:1，是全页最抢眼的色块）。
- **位置**：`src/components/sections/Hero.tsx` 的 `<br>` 断行 + `.hero-title-accent`；截图 `1440-hero.png` 文本块坐标 x 433–992 / y 254–556，第三行 y≈443–556。
- **判据**：① 排印规则——标题末行短于行长 30% 时构成「悬垂孤行」(hanging line)，专业排版要么重断行、要么把末行拉长；21%–33% 属于必须重排的区间。② 语义指向错误：整句的逻辑落点是「能运行的产品」，把 96px/900 的 accent 单独喂给「产品」两个泛词，等于用最重的视觉资源标注了信息量最低的两个字——这是典型的「大标题挑一个词换色」模板手法，而不是设计判断。③ 视觉重心：三行的重量分布是 1 : 1.2 : 0.4，眼睛读完第二行会掉进右下角那片 186px 的绿色，然后落空。
- **建议（CSS 级）**：改为两行，accent 落在动词短语上：
  ```tsx
  <h1>我们把设计<br /><span className="hero-title-accent">变成能运行的产品</span></h1>
  ```
  ```css
  .hero-title { max-width: 18ch; text-wrap: balance; }  /* 让两行长度接近 */
  .hero-title-accent { color: var(--c-txt); }            /* 或仅在「能运行」上加下划高光 */
  ```
  验收线：`h1` 最长行 / 最短行 ≤ 1.25。

### C3 · 「AI 深色 SaaS 落地页」套路七件套，六件齐全，差异化只剩中文文案
- **现象**：逐项实测（都是 computed style 直接读出来的，不是观感）：
  1. **网格背景**：`.light-field__grid` = `repeating-linear-gradient` 0°/90°，**96px 周期、1.5px 线宽、rgba(127,227,255,0.13)**；另有 `.light-field__ruler` 288px 周期的标尺线 0.2 透明度（装饰性第二层网格，无信息功能）。
  2. **双色荧光 accent**：`.light-field__fill` = 青 `rgba(127,227,255,0.075)` + 绿 `rgba(168,217,58,0.055)` 两个 radial。青绿双 accent 是这个模板最典型的指纹。
  3. **漂移光斑**：`.light-field__drift` radial 0.16/0.11 + 噪声层 opacity 0.035。
  4. **液态玻璃**：`backdrop-filter` 实测命中 **11 个元素** —— 7 个走 SVG 位移滤镜 `url(#hyalite-N)`（5 个 `.btn`、`.glass-contact`、`.btn--md`），4 个走 blur（`nav` blur 8px、`.cookie-toast` blur 12px、`.fab-to-top` 及其子节点 blur 8px）。SVG 位移滤镜本身做得不错，但用在「到处都是」的位置之后，就成了质感噪声而不是质感。
  5. **bento 卡片**：`#services` 实测 8 张卡 = 540×560（跨 2×2）+ 262×303 + 262×303 + 540×242 + 4×262×266，经典「一大 + 两小 + 一横 + 四小」拼图。
  6. **胶囊导航**：`header.nav` 高 66px、`border-radius: 999px`、`backdrop-filter: blur(8px)`，固定在 y=20。
  7. **FAB + 进度条 + cookie toast**：`.fab-to-top` 50% 圆 + blur 8px；`.scroll-progress` 2px 高 accent 绿；`.cookie-toast` 固定在左下（见 `1440-hero.png` 左下角）。
- **位置**：`src/styles/globals.css:213–320`（light-field 四层）、`:379–440`（glass 系列）、`:1491` 起（nav）、`src/components/ui/FloatingToolbar.tsx`。
- **判据**：同质化不在「用了深色」，而在**这些元素与业务没有因果关系**。网格/标尺暗示「工程精度」，但站内没有任何一处用网格承载测量、参数或对齐说明；青色是 `--c-info` 语义色，却被当成装饰光晕用，与单一的 accent 绿打架；玻璃在 9 处出现，稀释到每处都读不出「这是层叠关系」。真正的差异化在本站只有两处：中文文案的具体（「早期介入，现在只做…」「¥3,500 起 / 月」）和 `hyalite` 的折射实现——**这两点是真差异，其余五项是伪装成差异的套路**。
- **建议（CSS 级）**：删 3 件、留 2 件、改 1 件——
  ```css
  .light-field__ruler { display: none; }                 /* 第二层网格，纯装饰 */
  .light-field__grid   { opacity: .5; }                  /* 只保留一层，且只在 hero 内 */
  .light-field__fill   { background: radial-gradient(60% 45% at 30% 35%, rgba(168,217,58,.06), transparent 65%); } /* 去掉青色，回到单 accent */
  ```
  玻璃收敛到导航 + 联系卡两处：`.btn--primary.glass-btn { backdrop-filter: none; background: var(--c-accent); }`
  验收线：全站 `backdrop-filter` 命中数 ≤ 3；色相数 = 2（accent 绿 + 中性灰）。

## High

### H1 · 卡片与页底的「分隔度」只有 1.07:1，边框 1.46:1 —— 整片 bento 在实机上塌成一块
- **现象**：`.service-card` 背景 `#141414` vs `body` `#0A0A0A`，实算对比度 **1.07:1**；卡片边框 `#2E2E2E` vs 页底 **1.46:1**；`.pricing-card` 同样是 1.46:1。8 张卡 + 3 张价格卡 + 3 张案例卡全靠这 1.46 的边线定义形状。
- **位置**：`src/styles/globals.css:12–15`（`--c-panel: #141414` / `--c-line: #2E2E2E`），卡片规则见 `:1913` 附近（`.work-card` / `.service-card`）；截图 `1440-services.png`（卡片网格）与 `1440-pricing.png`。
- **判据**：WCAG 2.2 SC 1.4.11 Non-text Contrast 规定「识别界面组件边界所需的视觉信息」需 ≥3:1。卡片虽然不是控件，但在这个页面里卡片边界是**唯一**表达「8 项服务是 8 个并列条目」的信息——它承担结构功能，就得按 3:1 要求。1.46:1 在 P3 面板或强环境光下基本不可见，`.glass-float` 的 `translateY(-10px)` hover 又会把卡片推到背景之外，落差感被放大。
- **建议（CSS 级）**：站内其实已经有达标的令牌 `--c-border-ui: #666666`（globals.css:19，注释写明「交互控件的边界必须自己说得出这里能点」），把卡片边框接过去即可：
  ```css
  :root { --c-panel: #1A1A1A; }
  .service-card, .pricing-card, .work-card {
    border-color: var(--c-border-ui);                       /* #666666：对页底 3.45:1、对面板 3.03:1 */
    box-shadow: inset 0 1px 0 rgba(255,255,255,.07);        /* 顶边高光，让边界在暗部也能读 */
  }
  ```
  注意别按直觉取中间值：实测 `#5A5A5A` 对 `#0A0A0A` 只有 **2.87:1**（仍不达标），`#616161` 对页底 3.20:1 但对面板 `#1A1A1A` 只有 2.81:1——因为边框两侧都算相邻色，必须同时过页底与面板两个底。`#666666` 是这一约束下的最小可用值。

### H2 · 全站只有一种动效语言：6 个区块一律「上移 40px + 淡入」
- **现象**：源码里 6 处入场动画参数几乎逐字相同——
  `Services.tsx:37 gsap.set(cards,{y:40,opacity:0})` → `duration .4, stagger .08, expo.out`；
  `Works.tsx:181` 同参数、`CaseStudies.tsx:57` 同参数（stagger .1）、`Pricing.tsx:69` 同参数、`Process.tsx:57` 同参数；
  `About.tsx:60` 是唯一变体（y:24）；`Contact.tsx:24/28`（40 / 30）；`Hero.tsx:14` 0.8s。
  即：**12569px 的滚动过程中，每一个元素做的都是同一件事——从下方 40px 处淡入**，没有第二种动词，也没有任何动效携带信息（无计数、无流程推进、无图表/价格演化）。
- **位置**：上列文件行号；`src/components/sections/*.tsx`；截图无法表达，用 `1440-services.png` / `1440-works.png` 对照即可看出视觉结果的同一性。
- **判据**：Material Motion 的原则是 motion 表达层级与因果（shared axis / container transform / fade through），而不是统一装饰；Apple HIG《Motion》要求动效传达状态变化、不可用作纯装饰。「所有东西都从下面 40px 升起来」的直接后果是：用户无法从动效里读出「这一块和上一块是什么关系」——流程是 5 步、价格是 3 档、技术是 6 个平级条目，三者在动效上完全不可区分。
- **建议**：保留基础入场，但补一处**承载信息**的动效，并把差异化写进组件：
  ```css
  /* 1) 流程：用滚动驱动的进度线，而不是每行 fade */
  .process-step { --fill: 0; }
  .process-step__line { background: linear-gradient(var(--c-accent) calc(var(--fill) * 100%), var(--c-line) 0); }
  ```
  ```ts
  // 2) 价格：切换档位时金额滚动计数（count-up），其余区块保持 fade
  // 3) 技术资产：hover 播放 .webm（现在 preload=metadata、无 autoplay，只有 poster 静帧）
  ```
  验收线：全站动效动词 ≥3 种，且其中 ≥1 种只在信息变化时出现。

### H3 · 把「借来的可信度」放在自己的案例之前：第 3 屏是 6 个第三方开源项目的录屏
- **现象**：区块顺序与文档坐标（1440 档）：关于 1162 → 服务 2631 → **技术资产 4211** → 流程 5349 → **案例 6978** → 价格 8221 → 联系 9678。第 3 屏「技术资产」里是 6 个 `<video>`：`blender.webm / grafana.webm / metabase.webm / audacity.webm / penpot.webm / openshot.webm`，显示尺寸 **358×200**（源 640×360），`preload="metadata"`、无 autoplay，所以默认只显示 poster 静帧。自己的案例（3 张 `.case-card`）被压到第 5.5 屏之后。
- **位置**：`#works`（截图 `1440-works.png`）与 `#cases`（文档 y 6978）；组件 `Works.tsx` / `CaseStudies.tsx`；文案标题「技术资产 · 长期跟踪、拆解的开源工程」。
- **判据**：找外包的读者的决策顺序是「你们做过什么 → 怎么合作 → 多少钱 → 怎么联系」。现在的顺序把「我们看过别人的产品」放在「我们做过什么」之前 2767px，等于用他方资产先做能力背书——这类内容在采购语境里读作「没有自己的代表作」。另外 `<video>` 只有 poster、hover 才播，静态截图形态下 6 个项目看起来就是「6 张别人的产品截图」。
- **建议**：调整路由顺序而不是删内容——
  ```tsx
  // App.tsx：Cases 提到 Works 之前
  <Services /><Cases /><Works /><Process /><Pricing /><Contact />
  ```
  并把 `#works` 标题改为「工具链与拆解笔记」，每个卡片补一行「我们用它做过什么」的归属说明（哪一项能力、哪个项目），否则这 6 段录屏在任何位置都是负资产。

### H4 · 14 屏的长度对「3 类服务的小工作室」不成立，且最大区块是联系方式（2200px）
- **现象**：1440×900 下文档总高 **12569px = 14.0 屏**；390 档 **10783px = 12.8 屏**。各区块高度：about 1469 / services 1579 / works 1138 / process 1630 / cases 1242 / pricing 1457 / **contact 2200**。每个 section 上下各 `padding: 200px`（`--sp-10`），仅留白就吃掉 2800px。
- **位置**：`.section { padding: var(--sp-10) 0 }`（globals.css:510）；`#contact` 高 2200px。
- **判据**：Baymard 的落地页长度研究结论是「首页 5–7 屏内应完成主张—证据—价格—行动」，超过 7 屏后每屏的转化贡献迅速衰减；本站 14 屏里，价格在第 9.1 屏（y 8221），联系表单在第 10.8 屏（y 9678）。对一个只有 3 档标准品的工作室，等于让读者在看完 6 屏「我们很专业」之后才看到唯一的决策信息。
- **建议**：① `#about` 与 `#process` 合并为「我们怎么合作」（两块的文案高度重叠：都讲需求先行/进度透明/交付物）；② 联系方式拆成「联系卡 + 表单」两块并压到 1200px 以内；③ 留白从 `--sp-10` 收到 `120px`：
  ```css
  .section { padding: 120px 0; }
  @media (max-width: 767px) { .section { padding: 72px 0; } }
  ```
  目标：桌面 ≤ 9 屏，价格首次出现在第 6 屏之前。

## Medium

### M1 · 7 个分节头完全同构，唯一的差异来自「文案换行」
- **现象**：`.section-head` 实测高度：关于/服务/流程/案例/价格/联系 = **116.5px**（h2 76px + desc 16px），只有技术资产 = **175.9px**——差的 59px 是因为它那句 41 字的 desc 换成了两行，不是设计意图。7 个区块的开口句式、字号、字重、间距逐项一致。
- **位置**：`.section-head`（globals.css:533），7 处调用；截图 `1440-services.png` 与 `1440-pricing.png` 的顶部可直接对照。
- **判据**：分节头是滚动里唯一的「章节锚点」，同构意味着读者每次滚动都收到同一种信号，章节感消失；且 76px 的 h2 与 16px 的 desc 之间有 60px 的固定空档，desc 永远像 h2 的脚注而不是导语。
- **建议**：至少给 2 个区块换构图（不是换字号）：
  ```css
  /* 变体 A：左侧竖排编号 + 右侧标题 */
  .section-head--split { display: grid; grid-template-columns: 96px 1fr; align-items: start; }
  .section-head--split .section-head__index { writing-mode: vertical-rl; color: var(--c-txt-3); font-size: 12px; letter-spacing: .28em; }
  /* 变体 B：desc 提到 h2 之上，作为 kicker */
  .section-head--kicker { display: flex; flex-direction: column-reverse; gap: 8px; }
  ```

### M2 · 五套圆角语言并存：卡片 0 / 按钮 14 / 玻璃卡 20 / 导航 999 / FAB 50%
- **现象**：同屏可数到 `0px`（`.service-card`、`.work-card`、"0 0 14px 14px"）、`8px`、`14px`（按钮、cookie toast）、`20px`（`.glass-contact`、`.pricing-card`）、`999px`（导航、filter 胶囊、footer 链接）、`50%`（FAB）。令牌表里其实写好了 `--r-xs:4 / --r-sm:8 / --r-md:14 / --r-lg:20 / --r-xl:28 / --r-pill:999`（globals.css:42–47），但卡片绕过了令牌直接写 0。
- **位置**：`.service-card`（截图 `1440-services.png`，实测 `border-radius: 0px`）、`.pricing-card: 20px`、`.btn: 14px`、`header.nav: 999px`、`.fab-to-top: 50%`。
- **判据**：HIG《Layout》要求同类元素共享同一套形状语义；token 表存在的意义就是禁止「这一处我想圆一点」。0px 的方卡与 14px 的按钮放在同一个箱体里，在 20px 的玻璃卡旁，读者无法建立「圆角越大层级越高/越可点」的规律。
- **建议**：
  ```css
  .service-card, .work-card, .case-card { border-radius: var(--r-lg); }  /* 与玻璃卡统一 20px */
  .fab-to-top { border-radius: var(--r-pill); }
  ```
  验收线：全站 `border-radius` 取值集合 ≤ 4（`--r-md` / `--r-lg` / `--r-pill` / `50%` 仅 FAB）。

### M3 · 首屏构图：内容列 687px，右侧 384px 全空，视觉重心落在左下 CTA 与 cookie 面板上
- **现象**：1440 档 `.hero > .container` 实测 `x 369–1056`（宽 687），其中 h1 文本宽 559；容器右侧到版心边缘留有 **384px 空场**，无任何对位元素（`.hero-panel` 在 DOM 中不存在，`hero-grid` 的 300px 右列没有渲染）。视觉实测（`1440-hero.png`）：正文块占视口 39%，左下角另有 `.cookie-toast` 固定面板，把重量进一步拉向左下。
- **位置**：`#top`（globals.css:1239 `.hero-grid { grid-template-columns: 1fr 300px }` 但右列无内容）；截图 `1440-hero.png`。
- **判据**：三分法——主视觉应落在 1/3 或 2/3 轴线上，并与对侧元素形成配重。当前重心轴在 x≈433–992（中心偏左约 15%），右侧 30% 是纯背景，读者视线在首屏找不到第二个落点，只能直接跳到 CTA（这解释了为什么 cookie 面板那么显眼）。
- **建议**：二选一，不要留空场——
  ```css
  /* A：把 687 列扩到版心，h1 用 --fs-display 压满 */
  .hero > .container { max-width: 1360px; }
  .hero-title { font-size: clamp(56px, 8vw, 120px); max-width: 20ch; }
  /* B：保留窄列，把现在空着的右栏填成「数据条」（4 项事实：交付周期 4–12 周 / 远程 / React 19 / 团队规模） */
  .hero-grid { grid-template-columns: minmax(0, 680px) 1fr; }
  ```
  B 方案的文案站内已有（about 里的 fact-row），搬过来即可，不需要新增内容。

### M4 · 品牌链接的 `color` 是浏览器默认链接色 `rgb(158,158,255)`，靠子元素各自覆盖才没露出来
- **现象**：`.brand`（`<a href="#top">`）computed `color = rgb(158, 158, 255)`，`.brand__text` 同值——这是 Chromium 的 UA 默认链接色，站内**没有任何规则**给 `a` 复位颜色（全表搜 `a { color }` 命中 0 条）。目前视觉上不露馅，是因为 `.brand__name` 被写死 `#F0F0F0`（16.17:1）、`.brand__latin` 被写死 `#B0B0B0`（8.49:1）。任何一次「直接在 `.brand` 里加文字」或子元素样式失效，品牌字样就会变成一只紫色 `#9E9EFF`。
- **位置**：`src/styles/globals.css:1491 .brand`（只声明 display/gap/`text-decoration`，无 color）；`src/components/layout/Navigation.tsx:47`。
- **判据**：色彩系统要求色相数 ≤2（accent 绿 + 中性灰）；当前暗藏第三个色相，且它对任何 `currentColor` 使用者（如 `.brand__mark` 之外的图标）都生效。
- **建议**：
  ```css
  a { color: inherit; }                       /* 全局复位，放在 base 层 */
  .brand__text { color: var(--c-txt); }
  .brand { color: var(--c-txt); }
  ```
  验收线：`document.querySelectorAll('a')` 中 computed color 属于 {#F0F0F0, #B0B0B0, #8A8A8A, #A8D93A, #0A0A0A} 之外的数量 = 0。

### M5 · 固定位置的 cookie 面板长期压住内容：1440 档盖住第一张价格卡，390 档盖住服务卡
- **现象**：`.cookie-toast` 是 `position: fixed; left: var(--sp-4); bottom: var(--sp-4)`（globals.css:2940–2955），`background: rgba(18,18,18,.94)` + `backdrop-filter: blur(12px)`，无自动收起。截图可验：`1440-pricing.png` 左下角面板压住第一张价格卡（「设计稿转线上」）的正文与「聊聊这个」按钮区域；`390-services.png` 同样压在服务卡下沿；`1440-hero.png` 压在首屏左下、与两个 CTA 处在同一视觉重量级。
- **位置**：`.cookie-toast`（globals.css:2940）；截图 `1440-pricing.png` / `390-services.png` / `1440-hero.png`。
- **判据**：HIG《Layout》要求浮层不得遮挡为完成任务所需的操作元素；价格卡的 CTA 是这条页面的转化终点，被一块 12px 模糊的常驻面板盖住，是「层级凌驾于内容之上」。CSS 注释（globals.css:2937）说明上一轮已经修过它的视觉权重（按钮同权重、不做诱导），但位置问题没修。
- **建议**：改成不遮内容的形态——底部整条 banner 贴边（不悬浮在内容上），或首屏内联一次、滚动 1 屏后收起：
  ```css
  .cookie-toast {
    left: 0; right: 0; bottom: 0;              /* 贴底整条 */
    border-radius: 0;                          /* 不再是一块悬浮玻璃 */
    padding: 16px var(--sp-5);
  }
  @media (max-width: 767px) { .cookie-toast { padding: 12px 16px; } }
  ```
  若必须保留悬浮形态，至少加 `bottom: calc(var(--sp-4) + env(safe-area-inset-bottom))` 并让它在用户滚动超过 1 屏后收起（`transform: translateY(120%)`）。

### M6 · 移动端触控目标低于 44pt：筛选胶囊 31px、汉堡 38×41、页脚按钮 36px
- **现象**：390 档实测 `<a>/<button>` 中高度 < 44 的：`.works-filter__btn` **31px**（字号 13px，6 个筛选按钮全部如此）、`.nav__burger` **38×41**、页脚 `.btn.btn--sm`（GitHub）**36px**。`.skip-link` 41px 属可接受例外（只在聚焦时出现）。
- **位置**：`.works-filter__btn`（globals.css 约 :1539）、`.nav__burger`、`.btn--sm`；截图 `390-services.png` 之上的 `#works` 区域。
- **判据**：Apple HIG 明确触控目标最小 44×44pt；WCAG 2.5.8 (AA) 是 24×24、2.5.5 (AAA) 是 44×44。31px 过了 AA 但有 13px 字高 + 6 个连排，实际误触率在横向滚动容器里更高。
- **建议**：
  ```css
  .works-filter__btn { min-height: 44px; padding: 12px 16px; }
  .nav__burger { min-width: 44px; min-height: 44px; }
  .btn--sm { min-height: 44px; }
  ```

### M7 · 移动端服务卡横向滚动没有可滚线索（右缘裁切在 617px，视口 390px）
- **现象**：390 档 `.service-card` 的 `getBoundingClientRect().right = 617px`（视口 390），`document.scrollWidth = 390` 说明是容器内部横向裁切而非页面溢出。截图 `390-services.png` 里第二张卡只露出左缘 **约 40–65px** 的一条，**没有**渐变遮罩、页点、箭头；`scrollbar` 被 `.services-grid::-webkit-scrollbar{display:none}` 关掉，`scroll-snap` 未声明。同时左下角的 `.cookie-toast` 固定面板压在同一屏的卡片区（见该截图左下）。
- **位置**：`#services .services-grid`（globals.css:1196–1207 的移动端规则）；截图 `390-services.png`。
- **判据**：横向滚动容器必须给出「右边还有内容」的可见线索（W3C WAI 的 carousel 模式与 HIG 的 paging 惯例都要求 affordance 或明确的可滚边界）。当前第二张卡只露 40px 的圆角边，在很多机型上会被当成渲染错误。
- **建议**：
  ```css
  .services-grid {
    scroll-snap-type: x mandatory;
    scroll-padding-inline: 24px;
    mask-image: linear-gradient(90deg, #000 0, #000 calc(100% - 48px), transparent 100%);
  }
  .services-grid > .service-card { scroll-snap-align: start; }
  ```

### M8 · 双 `¥` + 「起」的排版与中英混排细节不齐
- **现象**：价格卡里 `¥12,000` 用半角 `¥`（`.pricing-card__amount` 32px，实测文本节点 `¥12,000`）后面紧跟独立的 `起`；规格之间用 en dash `2–3 周`、`4–6 周`、`5–7 个页面`（一致，这点是对的），但 `¥3,500 起 / 月` 与前三条的 `¥xx,xxx 起` 断行结构不同；页脚的 `Built with …` 为英文句子接在中文版权行后，无空格分隔语境。另外 `<title>` 是 `🐴 屿作所 — 综合数字产品工作室`——emoji 进 title 会改变浏览器标签页宽度与收藏夹呈现，且与站内 `<h1>` 的中文语气无关。
- **位置**：`#pricing` 文案（`Pricing.tsx`）、`index.html` 的 `<title>`；截图 `1440-pricing.png`。
- **判据**：中英混排规范要求「中文与拉丁/数字之间留 1/4 空隙、货币符号与数字不拆行」；同一组价格卡应当共用一种「符号 + 数字 + 起」的断行方式。当前 3 档用 `¥12,000` + 换行 `起`，维护档用行内 `¥3,500 起 / 月`。
- **建议**：
  ```css
  .pricing-card__amount { white-space: nowrap; }        /* 符号与数字不拆行 */
  .pricing-card__amount .cny { font-size: .6em; margin-right: .12em; }  /* 把 ¥ 降一号，视觉重量交给数字 */
  ```
  `<title>` 去掉 emoji：`屿作所 — 综合数字产品工作室`。

### M9 · 一条 2px 的滚动进度条 + 胶囊导航 + FAB，三个「当前位置」指示器抢同一件事
- **现象**：`.scroll-progress` 实测 `height: 2px`、`background: rgb(168,217,58)`，滚动后在 1440 档宽 321px；同时导航已用 `nav--scrolled` 加背景 + 模糊（backdrop-filter blur 8px）表达「已离开首屏」，`.fab-to-top` 50% 圆再表达一次「你在页面中间」。三处都在回答「你现在在哪」。
- **位置**：globals.css `.scroll-progress`；`src/components/ui/FloatingToolbar.tsx`；截图 `1440-hero.png`（顶部导航）与 `1440-services.png`（nav--scrolled 态）。
- **判据**：一条 2px 的进度条在 12569px 的页面上不提供可用的位置信息（321px / 12569px 的位移比在视觉上不可读），它只提供「有进度」的装饰感；而同一个语义被三个组件重复表达，属于典型的模板件堆叠。
- **建议**：删掉 `.scroll-progress`（信息量为 0），或把它升级成有语义的：导航内 6 个圆点按 `IntersectionObserver` 点亮当前区块——
  ```css
  .scroll-progress { display: none; }
  .nav__dot[data-active='true'] { background: var(--c-accent); }
  ```

## 结论

判定：**不达标（NEEDS REWORK）**。上一轮修的对比度、字库接线、LCP 都是真的（本报告复算全部达标），但**审美与差异化层面仍是「AI 深色 SaaS 模板 + 中文文案」**：

- 层级问题不是微调，是令牌用错（C1，`--fs-h1` 被区块标题占用，手机端层级直接倒置）。
- 首屏的核心手法（C2）是三行断句 + 末行单字换 accent，属于模板动作，且末行长度只有 21%–33%，排印上不成立。
- 同质化七件套齐全六件（C3），其中「网格 + 标尺 + 双色荧光 + 9 处玻璃」里至少有 4 件与业务无因果关系。
- 结构与信息的先后顺序（H3/H4）让「借来的可信度」排在「自己的案例」前面 2767px、价格排在第 9.1 屏。

**最小返工集**（按投入产出排）：C1 令牌改一行 → C2 断行改一处 → H1 两个色彩令牌 → H2 加一处信息型动效 → H3 调 `App.tsx` 区块顺序 → C3 删 ruler、去青色、玻璃收到 ≤3 处。这六步不动视觉风格的大盘，但能同时解决层级、套路与结构三件事。
