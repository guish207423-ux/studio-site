### 逐项说明

**1. axe。** 两站 `axe.run(document)` 均返回 `violations: []`，但 `incomplete` 里 `color-contrast` 分别有 118 / 138 个节点——这些节点的背景是渐变或图片，axe 主动放弃判定。所以「axe 0 违规」= 「有 118 处对比度根本没测」，不能当成 AA 达标证据。`video-caption` 在屿作所另有 6 处 incomplete（装饰性循环视频，无语音内容，可接受）。

**2. 对比度复算。** 自写脚本遍历文本节点 → 逐层合成 `background-color`（含 alpha）→ WCAG 相对亮度求比值；对 27 个落在渐变/图片背景上的节点改用**像素法**（把文字临时设为 transparent 后截图像素取中位数）。两轮独立测量结果一致（4.02–4.33 区间，均 <4.5）。

**3. 键盘。** 屿作所 82 个停靠点，逐点读 `outline*` / `boxShadow` / `background` / `border` 并与克隆节点（`:focus` 不生效）的基线对比：81 个有可见焦点环，`input.footer__newsletter-input` 完全无变化。焦点顺序 1→82 与视觉顺序一致，未发现键盘陷阱；skip-link（`a.skip-link`）第 1 个 Tab 即可见（x=651,y=0，2px 实线 accent 环）。软件目录站第 1 个 Tab 直接落在 `a.logo`——没有 skip-link。

**4. 移动端 390。** 屿作所：抽屉可用 Enter 打开、`aria-expanded` 正确、Esc 能关闭、`body.overflow` 正确切换、打开后 4 次 Tab 全部落在抽屉内（无逃逸）；但打开时焦点**不进入**抽屉，Esc 关闭后焦点**留在已移到 y=844 的 `.drawer__link` 上**。FAB 菜单 `aria-expanded` 能变 true，Esc 后仍为 true（不关）。Cookie 提示 `role="dialog" aria-label="Cookie 使用提示"`，302×129，两个按钮 60×40。软件目录站：68 个可交互元素里 67 个至少一边 <44px；头部 5 个导航链接被压到 26×22 且无折叠菜单。

**5. 语义。** 屿作所：landmark 齐全（`nav[aria-label=主导航]`、`main`、`nav[aria-label=页脚导航]`、`footer`），标题 h1→h2→h3 无跳级，表单 5 个控件全部有 `<label>`，31 个 svg 均在 `aria-hidden` 容器内或由 `aria-label` 命名，AX 树里 45 link / 17 button / 6 tab / 4 textbox / 1 combobox **全部有可访问名**。软件目录站：`input.search-bar__input` 无 `<label>`、无 `aria-label`，可访问名只能由 placeholder 提供；12 个 `span.software-card__thumb-letter` 未 `aria-hidden`，在 AX 树里作为单字符 StaticText（"V"、"G"、"P"…）暴露。

**6. 动效与缩放。** `prefers-reduced-motion: reduce` 下屿作所 `.marquee` 的 `animation-name: none`、1.2s 前后 `transform` 均为 `none`（不移动），`work-card__hint` 在 reduce 与 no-preference 下 opacity 均为 1（无内容丢失）；软件目录站 reduce 下 0 个残留动画。200% 缩放（视口 720×450）：两站页面级横向滚动均为 0；屿作所的 `.services-bento`（clientWidth 688 / scrollWidth 2512）、`.works-grid`（688/1826）、`.pricing-grid`（480/932）变为容器内横向滚动。

## 问题清单

### S1｜High｜关闭状态的移动端抽屉仍在 Tab 序列里，6 个不可见焦点停靠点
- 位置：`src/components/layout/Navigation.tsx:90-93`（`<nav id="drawer">` 始终渲染）；`src/styles/globals.css:1592-1610`（关闭态只有 `transform: translateY(100%)`，无 `visibility`/`display`/`inert`）
- 现象：1440×900 下第 9–14 个 Tab 停靠点是 `.drawer__link`（关于/服务/技术/案例/报价/联系），`getBoundingClientRect().y` = 940/1021/1101/1182/1262/1343，全部在 900px 视口之外；焦点环照常绘制在看不见的地方，且这 6 个链接与顶部导航完全重复。移动端关闭态同样在 y=844（视口底边）以下。
- 复现：1440×900 打开 `http://127.0.0.1:4173/` → 按 Tab 9 次 → `document.activeElement.className` 为 `drawer__link`，`rect.y` 940。
- 修法：关闭态加 `visibility: hidden` + `pointer-events: none`，或给 `<nav id="drawer">` 在 `drawerOpen === false` 时加 `inert` / `aria-hidden="true"` 并把子链接 `tabIndex={-1}`；打开时同步移除。

### S2｜High｜高亮报价卡正文与「起」对比度 4.02:1 / 4.17:1（<4.5:1）
- 位置：`src/styles/globals.css:2447`（`.pricing-card__desc`，13px，`--c-txt-3` = #8A8A8A）、`:2466`（`.pricing-card__period`，14px，同色）；触发元素 `src/components/sections/Pricing.tsx:94,97`
- 现象：三张报价卡里「官网重做」是推荐高亮卡，背景是 `linear-gradient(rgba(255,255,255,.04) → rgb(26,26,26))` 叠加绿色辉光。像素实测背景为 rgb(37,47,38)，#8A8A8A 文本比值 **4.02:1**；「起」背景 rgb(36,44,35)，比值 **4.17:1**。另两张卡背景为 rgb(20,20,20)，同色文本 5.34:1 合格——所以问题只出现在高亮卡，静态色值表算不出来，axe 也判 incomplete。
- 复现：1440×900 滚动到 `#pricing` → 把 `.pricing-card__desc` 文字设为 transparent → 截该元素矩形 → 像素中位数 rgb(37,47,38) → 与 #8A8A8A 求比值 4.02。两轮测量：4.21/4.33 与 4.02/4.17，均 <4.5。
- 修法：高亮卡内这两个选择器改用 `--c-txt-2`（#B0B0B0，实测同背景 7.3:1），或把辉光层 `opacity` 降低到不改变文字局部背景亮度。

### S3｜High｜页脚订阅输入框完全没有焦点指示
- 位置：`src/styles/globals.css:1162-1172`（`.footer__newsletter-input { outline: none }`，无 `:focus`/`:focus-visible` 规则）；元素 `src/components/layout/Footer.tsx:66-74`
- 现象：82 个 Tab 停靠点中唯一一个「聚焦前后计算样式完全相同」的元素——`outline-style: none`、`box-shadow: none`、`background-color`/`border-color`/`color` 与克隆节点基线逐项相等。
- 复现：1440 打开首页 → Tab 到页脚「你的邮箱地址」输入框 → `getComputedStyle(el)` 的 `outlineStyle` 为 `none`，`boxShadow` 为 `none`，视觉上无任何变化。
- 修法：删掉 `outline: none`，或补 `.footer__newsletter-input:focus-visible { outline: 2px solid var(--c-accent); outline-offset: 2px; }`（与 `.form-input:focus` 同款）。

### S4｜Med｜移动端抽屉：打开时焦点不进入，Esc 关闭后焦点丢在屏外链接上
- 位置：`src/components/layout/Navigation.tsx:22-32`（Esc 只做 `setDrawerOpen(false)`，无焦点管理）、`:64-68`（burger 无 `ref`/无 focus 转移）
- 现象：390×844 下 Enter 打开抽屉 → `document.activeElement` 仍是 `button.nav__burger`；Esc 关闭 → `drawer--open` 移除、`body.overflow` 恢复 `visible`，但 `document.activeElement` 是 `a.drawer__link`，其 rect.y = 844（已滑出视口）。之后按 Tab 会从屏外继续。
- 复现：390×844 → `document.querySelector('.nav__burger').focus()` → Enter → Esc → 读 `document.activeElement.className` = `drawer__link`，`getBoundingClientRect().y` = 844。
- 修法：打开时把焦点移到第一个 `.drawer__link`；关闭时 `burgerRef.current.focus()`。

### S5｜Med｜FAB 展开菜单不响应 Esc，焦点不进入面板
- 位置：`src/components/ui/FloatingToolbar.tsx`（`.fab` 的 `aria-expanded` 状态机）；样式 `src/styles/globals.css:2849`
- 现象：390×844 下 Enter 打开 `.fab` → `aria-expanded="true"`、`.fab-group` 出现微信入口；按 Esc 后 `aria-expanded` 仍为 `"true"`（未关闭），焦点始终停在 `button.fab`。
- 复现：390 → 聚焦 `.fab` → Enter → Esc → `document.querySelector('.fab').getAttribute('aria-expanded')` 返回 `"true"`。
- 修法：给 FAB 面板加与抽屉一致的 `keydown` Esc 处理并把焦点移入首个菜单项；关闭后回焦 `.fab`。

### S6｜Med｜软件目录站搜索框无可访问名（只有 placeholder）
- 位置：`src/App.tsx:448-455`（`input.search-bar__input`，无 `aria-label`、无 `<label>`、不在 `<label>` 内）；`src/styles/globals.css:202`
- 现象：`el.labels` 为空数组、`aria-label` 为 null、`aria-labelledby` 为 null；AX 树里 textbox 的名字由 placeholder「输入软件名称或其他关键词...」兜底。用户一旦输入，名字消失，语音控制/读屏无法再定位该框。axe 不报此条（accname 回退到 placeholder），所以「0 violations」漏掉了它。
- 复现：1440 打开 `http://127.0.0.1:5174/` → 读 `.search-bar__input` 的 `labels.length` = 0、`aria-label` = null。
- 修法：加 `aria-label="搜索软件"`，或补一个视觉隐藏的 `<label for>`。

### S7｜Med｜软件目录站 390px：67/68 个可交互元素小于 44px，且无移动端导航
- 位置：`src/styles/globals.css:150-161`（`.header-nav a` 无移动端规则）、`:387`（`.software-card__thumb`）、卡片按钮 `src/components/ui/SoftwareCard.tsx`
- 现象：390×844 实测——头部导航链接 26×22（5 个挤在 194px 内，无折叠菜单）、`software-card__fav-btn` 24×20（12 个）、`popular-searches__tag` 26 高（10 个）、`sort-btn` 27 高、`page-btn` 32×32、`sidebar__tag` 26 高（16 个）。全站仅 `.back-to-top` 44×44 达标。
- 复现：390×844 打开首页 → 遍历 `a,button,input,select,textarea,summary,[role=button]` 读 `getBoundingClientRect()` → 67 个满足 `w<44 || h<44`。
- 修法：移动端给这些控件 `min-height: 44px`（链接可用 padding 撑高并保持视觉尺寸），头部 5 个链接在 <768px 折叠进抽屉。

### S8｜Med｜软件目录站 12 个装饰字母进入无障碍树
- 位置：`src/components/ui/SoftwareCard.tsx:39`（`<span className="software-card__thumb-letter">{name.charAt(0)}</span>`）；样式 `src/styles/globals.css:387`
- 现象：72px、`rgba(255,255,255,0.05)` 的装饰首字母既没 `aria-hidden` 也没被 `aria-hidden` 容器包住，AX 树里作为单字符 StaticText 暴露（"V"、"G"、"P"、"M"…），读屏会在每张卡标题前念一个孤立字母；实测对比度 1.15:1。
- 复现：1440 打开首页 → `Accessibility.getFullAXTree` 过滤 `role=StaticText` → 出现 12 个单字符节点。
- 修法：`<span aria-hidden="true" className="software-card__thumb-letter">`。

### S9｜Low｜软件目录站缺 skip-link，头部与页脚导航 landmark 未命名
- 位置：`src/components/layout/Header.tsx:19`（`<nav className="header-nav">` 无 `aria-label`）；全站无 `a[href="#main"]`
- 现象：第 1 个 Tab 直接落在 `a.logo`，键盘用户要走完 6 个头部链接 + 搜索 + 10 个热门标签 + 7 个分类 + 4 个排序才能到结果列表；页面有 2 个 `<nav>`（`软件分类` 有名字，头部那个没有）。
- 复现：1440 打开首页 → 第 1 次 Tab → `document.activeElement` 为 `a.logo`。
- 修法：补 `a.skip-link[href="#main"]`（可复用屿作所 `globals.css:1747` 的实现），头部 nav 加 `aria-label="主导航"`。

### S10｜Low｜200% 缩放下屿作所三个区块退化为容器内横向滚动
- 位置：`src/styles/globals.css` 中 `.services-bento` / `.works-grid` / `.pricing-grid` 的横向布局
- 现象：视口 720×450（=1440 的 200%）时，页面级 `scrollWidth - innerWidth = 0`（无整页横向滚动），但 `.services-bento` 688/2512、`.works-grid` 688/1826、`.pricing-grid` 480/932——服务卡与案例卡的内容需要横向拖动才能读完，且这些容器的滚动条默认隐藏。
- 复现：`set_viewport_size({width:720,height:450})` → 读各容器 `scrollWidth/clientWidth`。
- 修法：<768px 时这三处改为纵向堆叠（或给出可见的滚动提示 + 键盘左右键支持）。

### S11｜Low｜桌面端 FAB 可聚焦但鼠标点不到
- 位置：`src/styles/globals.css:2828-2847`（`.fab-group` 默认 `opacity: 0`、`pointer-events` 只在 `.fab-group--visible` 时为 auto）；`src/components/ui/FloatingToolbar.tsx`
- 现象：1440 载入后 `.fab` 的 `pointer-events` 计算值为 `none`，但 `tabIndex` 为 0、仍在 Tab 序列末尾（第 82 个停靠点）——键盘能聚焦、鼠标点不动，且父容器默认 opacity 为 0。
- 复现：1440 打开首页 → `getComputedStyle(document.querySelector('.fab')).pointerEvents` = `none`，`tabIndex` = 0。
- 修法：不可见时给按钮 `tabIndex={-1}` 或 `visibility: hidden`，`--visible` 时再恢复。

### S12｜Low｜屿作所 Cookie 提示不接管焦点、按钮 40px 高
- 位置：`src/App.tsx`（`.cookie-toast`，`role="dialog"`）、`src/styles/globals.css:2967-2972`（`min-height: 40px`）
- 现象：390×844 下提示条 302×129 固定在 y=627–756，`role="dialog"` 却没有 `aria-modal`，出现时焦点不被移入、两个按钮 60×40（<44）。开发者已提到「Cookie 遮挡」，此处补的是焦点与尺寸两项可复现数据。
- 复现：390 打开首页（清 localStorage）→ 读 `.cookie-toast` 的 rect 与两个按钮 rect，`document.activeElement` 为 body。
- 修法：出现时聚焦「接受」，按钮 `min-height: 44px`。

### S13｜Low｜软件目录站 31 个图标 svg 未 `aria-hidden` 也无名字
- 位置：`src/components/ui/SoftwareCard.tsx`、`src/components/layout/Sidebar.tsx`、`Footer.tsx` 内的 inline svg（43 个 svg 中 31 个既不在 `aria-hidden` 容器内、也没有 `aria-label`/`<title>`、宿主元素也无名字）
- 现象：AX 树里这些 svg 作为无名字的 graphic 暴露，读屏会念「图形」但不说明是什么；axe 的 `svg-img-alt` 只覆盖 `role="img"`，因此 0 违规不含此项。
- 复现：1440 打开首页 → 遍历 `svg` 统计 `aria-hidden` / 祖先 `aria-hidden` / `aria-label` / `<title>` → exposedBare = 31。
- 修法：装饰图标统一加 `aria-hidden="true"`（屿作所 31 个 svg 已是 0 暴露，可参照其写法）。
