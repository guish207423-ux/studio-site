# 决策记录 — 官网（studio-site）

每条格式：**决策 → 依据（可复核）→ 代价 / 何时该推翻**。
只记录"有取舍"的决策；纯实现细节不进这里。

## 3. 中文不打包 webfont

- **决策**：拉丁展示字自托管（Archivo Black / Geist，只取 latin 子集），中文走系统栈
  （PingFang SC / HarmonyOS Sans SC / Source Han Sans SC / Noto Sans CJK SC / Microsoft YaHei）。
- **依据**：Noto Sans SC 子集化后 26 个分片共 1.29MB，Slow4G 下 LCP 3.96s / FCP 2.21s；
  去掉后 FCP 回到 1.5s 量级。苹果中国官网同样用系统苹方。
- **代价**：跨平台字形略有差异；这是已知且可接受的。

## 4. 静态首屏壳 + 构建期注入数字

- **决策**：`index.html` 内手写首屏真实标记，数字用 Vite `transformIndexHtml` 从数据文件数出来注入。
- **依据**：纯 CSR 首屏 FCP == LCP（目录站 2768ms、官网 3612ms），即 JS 执行前屏幕上什么都没有。
- **代价**：壳与组件必须逐字一致 —— 用 `scripts/check-shell.mjs` 守（连 `<br>` 数量都要比）。

## 5. 移动端：抽屉导航 + 关闭态 inert

- **决策**：`<900px` 用汉堡 + 抽屉；关闭态 `inert` + `aria-hidden`，Esc 关闭并把焦点交还汉堡。
- **依据**：原状 67/68 个可交互元素触控高度 < 44px，且无移动导航（a11y 评审 S7）；
  官网关闭态抽屉 6 个链接仍在 Tab 序列（S1）。
- **代价**：多一个组件状态；金额极小。

## 7. 官网玻璃收敛到两处

- **决策**：hyalite 折射只保留 `.glass-nav` 与 `.glass-contact`；按钮回实心表面，
  主 CTA 用实心品牌绿 `rgb(168,217,58)`。
- **依据**：原先 7 个元素挂折射（`filter[id^=hyalite]` 实测 12 个），"哪里都是玻璃 = 没有一处是玻璃"；
  苹果只在导航与模态用材质。收敛后 filter 12 → 2，主按钮对比度 8.9:1。
- **何时该推翻**：若品牌方向回到"材质驱动"，需同时提供至少两处非玻璃对照组，否则会退回 AI 落地页观感。

## 8. 卡片用"表面分层"而不是 3:1 硬边

- **决策**：卡片 `background:#131313` + `border: rgba(255,255,255,.075)` + 顶部内高光。
- **依据**：按 WCAG 1.4.11 严格读法做的 `#666` 硬边，实机是一圈线框感；语义上 1.4.11 管的是
  控件（按钮/输入框），容器分组靠表面亮度差更接近 Linear / Vercel / Raycast 的实装。
- **代价**：自动化对比度检查不会覆盖容器边界 —— 这是有意识的偏离，评审需人工确认分组可读。

## 9. 不做字体 preload（实测否定）

- **决策**：不预加载 display 字体，只靠 `@font-face` + `font-display: swap`。
- **依据**：加 `<link rel="preload" as="font">` 后 Slow4G 实测**更慢**：官网 708 → 840–884ms，
  目录站 1216 → 1320–1328ms。原因：首屏主标题是中文，走系统栈；display 字体只服务少量拉丁字形，
  不在关键路径上，而慢网下提前抢带宽会把 HTML/CSS/JS 往后推。
- **判据**：要不要 preload，只问一句「去掉它，首屏会不会缺字形/缺图」。答"不会"就别 preload。
